# Telegram Publisher

Локальное графическое приложение для подготовки и публикации постов в Telegram.

## Возможности текущей версии

- Оконный интерфейс на Tkinter.
- Визуальный редактор автоматически открывается при запуске и содержит выбор канала, способа публикации и команду отправки.
- Импорт публикаций по URL: сначала проверяется WordPress REST API, затем извлекается основное содержимое HTML-страницы.
- Импорт локальных файлов TXT, HTML, Markdown, DOCX и ODT с преобразованием в HTML для дальнейшего редактирования.
- Вставка текста и изображений из буфера обмена сочетанием Ctrl+V сохраняет доступное браузеру форматирование; контекстное меню по правой кнопке мыши включает вырезание, копирование и вставку.
- Доступны жирный/курсивный/подчёркнутый/зачёркнутый текст, заголовки H1–H6, цитаты, списки, таблицы, ссылки и единая команда «Медиа по URL» для вставки изображения или видео.
- Управление несколькими профилями каналов и выбор канала перед публикацией.
- Хранение токенов ботов в системном хранилище секретов Windows; в файле настроек сохраняются только названия профилей и идентификаторы каналов.
- Импорт первого профиля из локального файла `.env`, если он существует.
- Предварительный подсчёт длины текста и выбор способа публикации по длине и наличию изображения.
- Перед отправкой обычных сообщений через `sendMessage` открывается окно финальной правки с точным содержимым поля `text`; отправка подтверждается кнопкой «Отправить», а «Отмена» возвращает в визуальный редактор.
- Короткий текст можно отправить как подпись к изображению.
- Поддержка Bot API `sendRichMessage`: до 32768 символов, HTML-форматирование и встроенное изображение.
- Опциональная разбивка текста на серию обычных или рич-сообщений.
- Отображение ошибок и результата отправки.


## Как публикуется медиа в обычных сообщениях

Обычные сообщения и рич-сообщения используют разные способы отправки медиа:

- **Обычное сообщение** отправляется методом `sendMessage`. Если в редакторе есть одно изображение или видео с публичным URL, соответствующий тег удаляется из текста, а в конец сообщения добавляется ссылка с тремя символами нулевой ширины (U+200B), например `<a href="https://example.org/image.jpg">\u200b\u200b\u200b</a>`. Для выбора именно этой ссылки в Bot API передаётся `link_preview_options.url`; поэтому превью не зависит от других ссылок в тексте, а ссылка не создаёт отступ в начале поста. В запрос `sendMessage` не добавляются поля `media` или `rich_message`.
- **Рич-сообщение** отправляется методом `sendRichMessage`. В нём медиа задаётся через `media`, а в HTML используется элемент `<img src="tg://photo?id=…">` или `<video src="tg://video?id=…">`. Этот механизм предназначен для рич-сообщений, а не для обычных.

Приём с невидимой ссылкой — отдельный обходной способ для обычного `sendMessage`; он использует `LinkPreviewOptions`, чтобы явно указать URL превью. При подготовке обычного текста последовательности из трёх и более переводов строки сводятся к двум: между абзацами остаётся ровно одна пустая строка. Он не превращает локальный файл или `data:image/…` в публичную ссылку: для этого способа изображение или видео должно быть доступно по публичному URL.

Правила редактора и публикации:

- В одном обычном сообщении допускается не более одного изображения или видео.
- В серии обычных сообщений ограничение действует отдельно для каждой части.
- В редакторе медиа остаётся видимым элементом. При публикации элемент заменяется невидимой ссылкой на тот же публичный URL.
- При вставке текста с сайта через `Ctrl+V` или пункт «Вставить» редактор проверяет изображения в HTML буфера. Он использует публичный URL из `src`, `data-src`, `data-original`, `data-lazy-src` или `srcset`; относительный URL разрешается только при наличии исходного URL страницы. Если определить публичный адрес не удалось, изображение удаляется из вставляемого HTML, а редактор показывает предупреждение. Текст и остальное форматирование сохраняются. После этого медиа можно добавить через кнопку «Медиа по URL».
- Обычное сообщение не может превратить локальное изображение или `data:image/…` в превью ссылки через `sendMessage`: для этого способа нужен публичный URL.

## Требования

- Python 3.11 или новее.
- Telegram-бот с правом публиковать сообщения в целевом канале.

## Установка для разработки

1. Создай виртуальное окружение: `py -m venv .venv`.
2. Установи проект и инструменты тестирования: `.venv\\Scripts\\python.exe -m pip install -e ".[dev]"`.
3. Запусти приложение: `.venv\\Scripts\\python.exe -m telegram_publisher`.

Активация окружения в PowerShell необязательна. Если политика выполнения сценариев блокирует `Activate.ps1`, используй команды через `.venv\\Scripts\\python.exe`.

## Настройка каналов

1. Нажми «Настроить каналы…».
2. Создай профиль, указав название, токен Telegram-бота и имя публичного канала (например, `@my_channel`) или числовой ID.
3. Добавь бота в канал и выдай ему право публикации.
4. При наличии нескольких профилей выбери нужный в списке «Канал» перед нажатием «Опубликовать».

Токены хранятся через системное хранилище учётных данных. В локальном файле настроек сохраняются только названия профилей и идентификаторы каналов. Не отправляй токен в чат и не добавляй его в Git.

Для обратной совместимости приложение ищет `.env` в текущей папке, рядом с проектом или рядом с собранным исполняемым файлом. Если сохранённых профилей нет и в `.env` заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, приложение автоматически создаёт профиль «Канал из .env» и сохраняет токен в системном хранилище, если оно доступно.

## Ограничения текущей версии

- Визуальный редактор объединяет подготовку и публикацию. Перед обычной отправкой можно проверить и отредактировать точное содержимое поля `text` метода `sendMessage`. Отмена финальной правки возвращает к визуальному редактору без отправки. Содержимое визуального редактора сохраняется независимо от результата публикации.
- Изображения и видео, присутствующие на веб-странице или в HTML-файле, импортируются по публичным URL. В документах DOCX и ODT импортируется текст и доступное форматирование; встроенные изображения таких документов не извлекаются.
- Обычное сообщение ограничено 4096 символами, подпись к изображению — 1024, рич-сообщение — 32768 символами.
- Автоматическая разбивка серии сначала наполняет каждую часть целыми абзацами. Если отдельный абзац превышает лимит, он разбивается по границам предложений; списки до превышения лимита считаются единым блоком, а слишком длинные списки разделяются по пунктам. Если форматирование пересекает границу частей, результат следует проверить вручную.
- При переключении в обычный режим неподдерживаемые элементы подсвечиваются. Заголовки преобразуются в жирный текст, таблицы — в строки с разделителями, а медиа заменяется скрытой ссылкой для предпросмотра.
- Перед публикацией приложение показывает подтверждение. Отправка нескольких частей не является транзакцией: при сетевой ошибке часть публикации может уже оказаться в канале.

## Проверки

Запуск тестов: `.venv\\Scripts\\python.exe -m pytest`.

### Отправка серий и ограничения Telegram

Обычные серии отправляются последовательно с паузой 3,2 секунды между сообщениями. Это консервативная настройка с учётом ограничения порядка 20 сообщений в минуту, которое Telegram документирует для групп; фактические ограничения каналов могут отличаться.

Если Telegram возвращает ошибку `RetryAfter` (flood control), приложение сохраняет подтверждённо отправленную часть серии и список сообщений, которые не были приняты. Кнопка «Дослать неопубликованное» открывает список остатка: каждое сообщение можно отредактировать или удалить. При повторной отправке приложение сначала выдерживает срок `retry_after`, указанный Telegram, затем продолжает отправку с паузами между сообщениями. Автоматического повтора без участия пользователя нет.
